# 华理跑步姬 iOS 2.0.6

这是原生 iPhone / iPad 工程，包含登录、模拟、自动、记录和地图，支持电脑代执行与云端 IPA 构建。2.0.6 将手动时长改为分钟、秒、毫秒，定位失败、坐标无效或校外时自动选择校园道路随机起点；开始前自动刷新缺失或过期的三点。最低 iOS 16，建议使用 Xcode 16 或更新版本。

2.0.6 已于 2026-10-14 通过云端 Xcode 编译、64 项规则/助手测试和 8 项原生 XCTest，并生成 ARM64 iPhone 真机 IPA。实际验证状态见 `verification.json`。尚未在实体 iPhone 上测试。

本次构建：[GitHub Actions](https://github.com/PbAc114514/huati-ios/actions/runs/38547932093)。云端验证记录只有与当前输入文件摘要一致时才适用于当前工程；安装包不含用户会话或苹果签名凭据。

## 只有 Windows：云端生成 IPA，再在 Windows 签名安装

工程随包包含 `.github/workflows/build-ios.yml`。云端使用 GitHub 提供的 macOS/Xcode 编译；Windows 无需安装 Xcode。流程已实际成功运行，现成 IPA 可直接交给自己的签名方式。下面的步骤用于日后重新编译源码。

1. 解压整个 `Huati-iOS-v2.0.6` 文件夹，创建自己的 GitHub 私有仓库。
2. 将解压文件夹的**内容**上传到仓库根目录，包括 `.github`、`Huati`、`HuatiTests`、`Huati.xcodeproj`、`Tests`、`tools`、`companion` 和四个 `.command` 文件。`.github/workflows/build-ios.yml` 必须位于仓库根目录的 `.github/workflows/` 下。不要上传自己的会话、配对文件、运行数据或签名材料。
3. GitHub 仓库 → **Actions → Build iPhone IPA → Run workflow**。若提示未启用 Actions，按界面开启。
4. 流程会运行本地定时/电脑执行测试、编译模拟器并运行 XCTest，再编译 ARM64 真机版本。全部成功后，下载 **Huati-v2.0.6-unsigned-IPA** 附件，解压得到 `Huati-v2.0.6-unsigned.ipa`。
5. 在 Windows 使用 [Sideloadly](https://sideloadly.io/) 或自己的有效苹果签名工具，对这个 IPA 签名并安装到自己的 iPhone。按工具提示连接手机、登录自己的 Apple ID，密码和验证码仅在工具内输入，不需要发送给本项目。
6. 按手机实际提示信任开发者并开启开发者模式。免费个人签名通常约七天需重新签名；付费签名仍受设备授权和配置有效期约束。

构建失败时，Actions 不会提供假 IPA。日志可下载排查。未签名 IPA 不能直接点击安装；本工程 ZIP 也不能通过改后缀成为 IPA。美术资源已随工程带齐。

## 机型与系统

| 手机 | 支持条件 |
| --- | --- |
| iPhone 8、8 Plus、X | 升级至该机支持的 iOS 16.x；无需 iOS 17 |
| iPhone XR、XS、XS Max、11 及更新机型 | iOS 16 或更新 |

同一个 ARM64 包覆盖以上机型，无需每台手机单独制作。最低系统与真机编译产物已检查，各机型的实际行为仍需实体手机安装确认。

## 在自己的 iPhone 上安装

1. 将整个工程文件夹传到 Mac 并解压，打开 `Huati.xcodeproj`。也可双击 `Open-in-Xcode.command`。工程已包含全部地图和美术资源，不需要电脑上的 E 盘文件夹。
2. Xcode → Settings → Accounts，添加自己的 Apple ID；选择工程中的 **Huati** 应用目标，在 **Signing & Capabilities** 勾选 **Automatically manage signing**，选择自己的 Team。
3. 若应用标识被其他团队占用，将 Bundle Identifier 改为自己的唯一名称，例如 `com.yourname.huatirun`。后台任务标识由工程内常量和 Info.plist 配对，保持它们一致即可。
4. 用数据线连接 iPhone，信任电脑；按系统要求在“设置 → 隐私与安全性 → 开发者模式”中开启开发者模式，必要时重启。
5. Xcode 顶部选择自己的 iPhone 作为运行设备，点击运行按钮。若出现开发者信任提示，按手机“设置 → 通用 → VPN 与设备管理”中的实际提示信任自己的开发者。
6. 打开“华理跑步姬”，在“账号”页用手机号登录，或从“文件”App 导入安卓端导出的 `huati-session.json`。

免费 Apple ID 通常可以经 Xcode 安装到自己的设备，个人开发签名通常约 7 天后需重新安装。需要长期或多设备安装时，使用自己的有效开发者签名与对应设备配置；没有签名的工程 ZIP、APK 或任意改后缀文件都不能直接安装到 iPhone。

## 导出签名 IPA

具备可用的开发者团队、证书和设备配置后，可在 Xcode → Product → Archive 中导出，或在 Mac 终端运行：

```sh
chmod +x ./*.command
./Build-iOS.command YOURTEAMID debugging
```

`YOURTEAMID` 替换为自己的十位 Team ID。脚本使用 Xcode 自动签名，将 IPA 写入 `Exports/IPA/`；已在开发者配置中授权的设备才能安装。`release-testing` 对应注册设备的发布测试方式。脚本不接收 Apple ID 密码、不包含证书或私钥。

已有其他签名工具时，可以由具备 Mac/Xcode 的环境先编译导出 App/IPA，再使用自己的工具签名。仅有签名凭证不能在 Windows 上将 APK 转成 iOS App。

## 与安卓的对应功能

- 应用名称与指定 Q 版头部图标、当前 19 张随机开屏插画、3 秒开屏、两列竖排标题和随机跑步 tips。
- 三张淡蓝几何背景、浅色半透明卡片、36 张 Q 版普通/跑步配对人物；底栏五个页面，账号头像按 38.4 点显示，模块人物按 74.4 × 81.6 点显示。
- 手机短信/密码登录，会话文件导入导出；密码和验证码不落盘。会话与记录使用 AES-GCM 加密文件，密钥存在仅本设备钥匙串。
- 随机三点、分钟/秒/毫秒手动参数（总时长 1–120 分钟）、路线预览、暂停/继续/舍弃、本次服务器记录查询；明确判无效也继续提交。时长保存到毫秒，实际启动与网络提交仍受系统调度影响。
- 06:00–21:00 自选每日开始时间、提前两分钟准备、06:00 后刷新每日数据与三点、定位失败或校外的随机校内模拟起点。时长在 720001–959999 毫秒中随机选一次并保存。
- 同日换到后续新时间可以再计划；同一天同一时间保存尝试标记，避免重复创建。服务器每日有效次数规则依旧适用。
- 校园道路路线经过三点，手动目标 ±0.5 公里且至少 2.1 公里；自动只要求经过三点及至少 2.1 公里。
- 离线校园地图缩放 1–6 倍、拖动、双击、缩放按钮、点位查看与点位目录导入。
- 创建记录、自检与报告采用统一 Q 版头像提示界面；报告可选字与复制，不含会话、密码、手机号、坐标或网络正文。

## 定时、锁屏与提前两分钟准备

在“自动”页选择北京时间 06:00–21:00 的启动时间。时长沿用用户要求：每次随机大于 12 分钟、小于 16 分钟，保存到毫秒；经过三点且至少 2.1 公里，明确判无效也直接提交。

**电脑代执行是锁屏时尽量按时运行的可选方案。** iPhone App 负责设置和查看，自己的电脑提前两分钟选择校内模拟起点、刷新随机三点，到点开始，计满完整时长后提交。手机锁屏不影响电脑。电脑必须持续联网且不睡眠；网络、电脑重启或服务器响应仍可能造成延迟。设为 06:00 时，05:58 准备起点，等 06:00 接口开放后刷新三点并开始，因此会有必要的接口耗时。

首次在 Windows 启动随包 `companion` 助手，配置自己的 HTTPS 访问地址，在 App 的“自动 → 电脑代执行”导入助手生成的配对文件，然后“同步以上时间到电脑并开启”。完整步骤见 [companion/README.md](companion/README.md)。当前仅准备了助手和流程，未部署、未上传你的会话，也未启用真实任务。

电脑无法读取锁屏手机的实时 GPS，采用校内模拟起点。电脑接管后本机自动创建停用，防止两端重复。状态结果未知时使用原指令编号核实；创建、提交或轨迹上传未知时保留待核实状态，不自动重发。暂停、继续、舍弃和交回手机均在 App 内操作。

## 手机本机后台的实际限制

**iOS 不提供安卓式的精确后台闹钟。** 本工程注册 `BGProcessingTask` 并提供本地提醒，但 `earliestBeginDate` 只是最早可执行时间。iOS 决定实际唤醒时间，可能延迟、过期、不给执行机会或在处理中终止。因此，锁屏/后台情况下不能保证按时刷新三点、开始、计满后立即提交，通知也不会执行网络请求。

本机提前两分钟请求后台执行。新版会在系统允许的短时窗口内继续处理，计划或结束即将到达时尝试衔接请求；不会申请虚假的音频或持续后台 GPS 权限。系统晚唤醒时，未尝试的今日计划可在 21:00 前重新刷新三点并补启动，完整时长从实际开始计算；21:00 计划允许在该分钟内处理必要的唤醒延迟。已经创建的记录即使超过启动窗口仍继续处理，暂停记录不会自动继续。

前台会按计划检查和执行；可开启“前台使用时保持屏幕常亮”。返回应用后沿用原记录与原时长。只读校验被系统取消时保存重试；创建/提交或上传结果未知时保留待核实状态，不盲目重复发送。

后台权限首次需要手动设置：设置 → 通用 → 后台 App 刷新；关闭低电量模式，允许通知并保持联网。不要强制划掉应用；重启后先解锁并打开一次。苹果版只在准备阶段尝试取得当前位置，不持续采集后台位置；系统不给定位机会时采用校内模拟起点。

“一分钟后台自检”也是最早一分钟后可执行，系统可能延迟或不唤醒。到时间显示通知不等于自检通过，应查看报告中的“后台自检已唤醒”与匿名联网结果。

舍弃只停止本地流程，服务器已经创建的占位记录保留。未知校验或网络失败会暂停；提交或轨迹上传结果未知时需到官方小程序核实，不重复提交。模拟路线与步数不代表实际运动，成绩由服务器判定。

## 本地验证

Windows 在 UTC、上海和洛杉矶环境下运行本地规则及电脑助手回归测试，覆盖提前两分钟、06:00 开放、准点与晚唤醒、完整计时、断线、重启、重复指令、无效结果提交、真实道路图、三点和最低里程。电脑测试使用假接口，不登录真实账号或提交真实记录。具体数量见 `verification.json`，该文件也列出尚未进行的 Xcode/真机验证。

Mac 上执行：

```sh
chmod +x ./*.command
./Verify-iOS.command
```

脚本先编译模拟器版本，再在可用 iPhone 模拟器上运行 `HuatiTests`。测试使用演示数据，不发送登录或跑步请求。请在 Xcode 安装 iOS 16 或更新的运行时；本地脚本没有可用模拟器时只报告编译结果，云端流程要求模拟器测试实际完成。

## 源码与资源

`Huati/Core`：原生协议、加密存储、位置、计时与后台协调。`run-core.js` 是随包离线执行的本地路线/时间规则，通过系统 JavaScriptCore 调用；界面不是网页，不使用远程脚本。`Huati/UI` 是原生 SwiftUI。`Huati/Content` 包含全部资源，无会话文件或凭证。
